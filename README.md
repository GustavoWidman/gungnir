# Gungnir

A benchmark harness for AI coding agents across reasoning-effort levels and programming
languages. Gungnir drives each vendor's own agent CLI headless inside a sandbox, grades the
program the agent writes against hidden functional tests it never sees, times that program
against a reference solution in the same language on a dedicated machine, and exports every
sample as CSV tables for statistical analysis. A system under test is a harness, a model and an
effort level, so every claim is about that combination as shipped.

The study behind it is in progress. The manuscript is a draft in [`paper/`](paper/), with
research notes in [`paper/notes/`](paper/notes/).

## What a trial measures

A trial is one system on one scenario in one language, at one repetition. It moves through four
phases, each committed as a directory that is complete or absent:

| Phase | What it records |
|---|---|
| `run` | The agent's session in a sandbox: transcript, final workspace, turns, wall time, and token usage per request, with the vendor's quota readings |
| `grade` | An offline build, and every hidden case run in its own sandbox and compared on the host: pass, wrong answer, crash, timeout or out of memory per case, plus lizard complexity |
| `measure` | The passing program against the reference, in alternating ABBA blocks pinned to one isolated core: wall-time ratio with a 95% interval, instruction ratio and peak memory per workload |
| `report` | CSV tables of model samples: `trials`, `cases`, `functions`, `usage`, `quota`, `workloads` and `timings` |

A trial's state is derived from its committed records, never stored. Each record keeps the inputs
it was made from (prompt, workspace, hidden suite, workloads, toolchain store paths, protocol),
so a change to any of them marks exactly the affected phases stale.

Only a session that completed or was refused is a sample. Crashes, timeouts, provider errors
and rate limits are retried until the session ends on its own, and never reach the data.

## Sandbox

Every agent and every program under test runs in bubblewrap inside a transient systemd scope
with memory, task and time limits. A sandbox binds only the Nix closures of its toolchains,
never the whole store, so no hidden case or reference is reachable. Grading and measuring run
offline. An agent reaches the network only through a host-side CONNECT proxy that tunnels its
backend's allowlisted hosts on port 443 and logs every connection. For NVIDIA, whose free tier
refuses bursts of requests, the proxy relays the agent's model requests itself: it adds the API
key, so the agent holds none, and tries a refused request again for up to 10 minutes. The relay
also carries the requests of the backends whose endpoints the tunnel cannot reach: CLIProxyAPI
on port 8317, and LM Studio over plain HTTP on the local network.
Credentials are staged into an isolated home per attempt and redacted from every stored
transcript and log.

## Requirements

- Linux with a systemd user manager that delegates the `cpu`, `cpuset`, `io`, `memory` and
  `pids` controllers, and unprivileged user namespaces for bubblewrap.
- Nix with flakes. The dev shell provides the Rust toolchain, Typst and the
  `GUNGNIR_TOOLCHAINS` set of sandbox environments.
- A login or API key per backend, in the files `gungnir.toml` names:
  - `~/.config/gungnir/claude/oauth_token` for Anthropic, from `claude setup-token`;
  - `~/.config/gungnir/codex/` for OpenAI, a `CODEX_HOME` after `codex login`;
  - `~/.config/gungnir/glm/api_key` for Z.ai;
  - `~/.config/gungnir/nvidia/api_key` for NVIDIA;
  - `~/.config/gungnir/deepseek/api_key` for DeepSeek;
  - `~/.config/gungnir/cliproxy/api_key` for CLIProxyAPI;
  - `~/.config/gungnir/lmstudio/api_key` for LM Studio, which checks no key, so any placeholder
    such as `lm-studio` serves.
- For measuring, a quiet machine with `kernel.perf_event_paranoid` at 1 or less, ideally
  with isolated cores (`isolcpus`, `nohz_full`), where `measure` runs one lane on the first
  thread of each, and fixed clocks, which `clock_mhz` in an experiment's `[measure]` table
  checks. An experiment's `[machine]` table pins its measurements to one machine, and
  `gungnir measure` refuses any other.

## Usage

`nix build` produces the CLI wrapped with its sandbox toolchains and bubblewrap; below,
`gungnir` stands for `./result/bin/gungnir`. For development, `nix develop` provides the same
toolchains to `cargo run`.

```sh
gungnir plan experiments/study-openai.toml      # validate and print the trial matrix
gungnir check                                    # grade every reference solution
gungnir run experiments/study-openai.toml        # run pending trials until each is a sample
gungnir grade experiments/study-openai.toml      # grade committed runs
gungnir measure experiments/study-openai.toml    # on the pinned machine
gungnir report experiments/study-*.toml --out runs/report
gungnir index experiments/study-openai.toml experiments/study-claude.toml
```

| Command | Purpose |
|---|---|
| `plan` | Validate an experiment and print the trial matrix it expands to |
| `check` | Build and grade every reference solution, regenerating missing workloads |
| `run` | Run pending trials, one lane per backend, behind quota ceilings, deadlines and an error stop |
| `grade` | Grade committed runs offline against the hidden cases |
| `measure` | Time passing programs against the reference under the experiment's protocol, one comparison per measurement core (`--cores`) |
| `bench` | Time any workspace against a reference, or the reference against itself as an A/A test |
| `profile` | Sample one trial and its reference under perf and write flame graphs |
| `machine` | Print this machine's identity as a `[machine]` pin |
| `status` | Count each system's trials by stage, and the stale ones |
| `report` | Fold the committed records of experiments into CSV tables |
| `index` | Score each language on the gungnir index, with 95% bootstrap intervals, and write the scores as CSV with `--out` |

The gungnir index scores each language against the average language for the same model and
scenario on pass rate, tokens, session time, program speed and simplicity, where 100 is average
and higher is better. `index` counts a generation only once `--complete` of its cells (95% by
default) are graded at every effort of its model, and `--weight speed=0` reweighs or drops a dimension. `docs/architecture.md`
states the definition.

`run` takes `--quota-ceiling BACKEND[:WINDOW]=FRACTION` to stop a backend at a share of a
quota window, `--stop-at BACKEND=TIME`, `--max-errors N`, `--max-attempts N` and `--dry-run`.
Backends that publish their usage, such as Z.ai, are read from the host, and their lanes hold
before a window runs out (`--quota-hold`). The first Ctrl-C lets running agents finish; the
second kills them.

## Experiments

An experiment file names a matrix and how to run it:

```toml
name = "study-openai"
results = "../runs/study-openai"
repetitions = 1
scenarios = ["bigint-calc", "exact-cover", "json-path", "ledger", "line-diff", "regex-lite", "route-fuel", "tiny-vm"]
languages = ["python", "rust", "zig", "go", "c", "cpp", "javascript", "typescript"]

[machine]
cpu = "13th Gen Intel(R) Core(TM) i9-13900K"
host = "11b301add99fa61a4eb9f0a36eae41f1"

[pins]
codex = "0.166.0"

[budget]
wall = "4h"
idle = "30m"

[concurrency]
openai = 5

[[systems]]
model = "gpt-6-luna"
efforts = "all"
repetitions = 5

[[systems]]
model = "gpt-6.1-terra"
efforts = "all"
```

An optional `[measure]` table states the timing protocol with all three of its keys: `blocks`
ABBA blocks, each timing both programs `runs` times after `warmup` untimed runs. Without it an
experiment measures under 6 blocks of 3 runs and no warmup. The table may add `clock_mhz`, the
one frequency every measurement core's clock is held at: `measure` then refuses to start unless
each core's cpufreq `scaling_min_freq` and `scaling_max_freq` are both that frequency, and
`bench --clock-mhz` makes the same check for an A/A test. A measurement made under another
protocol, another clock included, is stale, so `measure` takes it again and `status` and
`report` count it as stale.

Trials run repetition by repetition, so a run stopped early leaves the matrix evenly covered.
Results live under `runs/`, which is not tracked.

## Scope and limits

- Systems run on vendor subscriptions, on NVIDIA's free API, behind a CLIProxyAPI instance and
  on local hardware through LM Studio, through vendor harnesses.
  Results describe a harness, model and effort together; the harness is part of what is
  measured.
- Costs are list-price equivalents computed from token usage and dated price tables, not bills.
- An NVIDIA session's wall time includes the relay's waits on the free tier's throttling, which
  each attempt's `egress.jsonl` records.
- Claude Code cuts each response of a model it does not know at 32,000 output tokens, reasoning
  included, and tells the model to resume. After three such cuts in a row it ends the session
  in an error, which is no sample, but a session that resumed and completed is one, and its
  transcript holds the resume turn. A model whose catalog entry sets `max-output-tokens`
  launches with Claude Code's cap raised to it: GLM-5.3 and GLM-5.3-Flash state 131,072, which
  Claude Code 2.1.316 lowers to its own maximum of 128,000.
- Token categories are not comparable across vendors as reported: only Anthropic reports cache
  writes, while OpenAI, Z.ai and NVIDIA count them as plain input. Compare new input (uncached
  input plus cache writes), cache reads and output separately.
- Pass rates near 100% stop separating systems, which is why the study scenarios are harder
  than the pilot's. Systems that still pass nearly everything differ in program speed, tokens
  and cost.
- Performance claims need every repetition measured on the pinned machine. One repetition per
  configuration describes one program, not a system.

## Repository layout

- `src/`: the `gungnir` crate, a library and a thin binary (see the crate map in
  [AGENTS.md](AGENTS.md))
- `languages/<id>/`: toolchain profiles with prompt preamble and starting template
- `scenarios/<id>/`: specs, examples, hidden cases, generators, workload digests and references
- `experiments/`: experiment matrices
- `nix/`: the sandbox toolchain environments and the offline TypeScript checker
- `paper/`: the manuscript (`typst compile paper/main.typ`), bibliography and research notes;
  `paper/analysis/` turns a report and an index of the study experiments into the figures and
  numbers the manuscript reads:

  ```sh
  gungnir report experiments/study-openai.toml experiments/study-claude.toml --out runs/report/study
  gungnir index experiments/study-openai.toml experiments/study-claude.toml --out runs/index/study
  cd paper
  python3 -m analysis ../runs/report/study ../runs/index/study ../runs .
  python3 -m analysis.crashes ../runs/report/study ../runs/index/study ../runs ../scenarios .
  ```
- `docs/architecture.md`: the design contract
